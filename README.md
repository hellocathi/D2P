# D2P · 健康内容与素材生产工作台

使用 Markdown 制作医疗健康科普、疾病知识及药品宣传长图。支持模板切换、PNG/JPEG、最多50篇串行任务、本地上传与明确标识的 SCM Mock、URL清单和ZIP导出。不负责短信编辑或发送。

## 运行

需要 Node.js 22+，推荐24。在仓库根目录运行：

```bash
npm ci
npm run check
npm start
```

生产服务器同时提供前端页面与上传API，默认端口3001。开发时单独运行 `npm run dev`，会同时启动前端和上传API，浏览器打开终端显示的Vite地址即可。请勿同时用同一API端口运行 `npm start`。开发上传URL默认通过Vite同源代理，避免图片下载跨域失败。

环境变量由进程注入（不会自动加载 `.env`）：

```bash
PUBLIC_BASE_URL=https://materials.example.com UPLOAD_DIR=/data/uploads PORT=3001 npm start
```

`PUBLIC_BASE_URL` 必须设为使用者和下游可访问的真实地址；默认 localhost 只适用于本机。上传文件目录应挂载持久化卷。系统面向可信本地/内网部署，公开部署请在反向代理层配置访问控制和请求限制。

## 使用

1. 在「制作记录」点击「新建制作」，或导入Markdown、图片、目录、ZIP。
2. 在「制作预览」按需编辑内容、选择模板，设置PNG/JPEG及倍率，然后点击「保存制作」。保存仅记录作品，不生成图片、不上传或下载。
3. 制作记录累计保存每份作品。点击标题或「查看 / 编辑」重新打开，修改后保存会更新同一作品的版本。
4. 在记录中单独点击「生成 URL」，或勾选多份作品后点击「批量生成 URL」。系统按顺序截图和上传，仅回填图片URL，不自动下载文件。最多50份，每个作品使用其保存时的独立图片素材。
5. URL生成后可单张下载、下载所选图片ZIP或导出URL清单。未改动且已生成URL的作品再次批量导出时直接复用URL。
6. 在「导出进度」查看单任务状态、取消或重试。在「导出历史」查看此前成功的交付记录。

制作记录、编辑草稿、任务快照及导出历史保存在当前浏览器的IndexedDB中。保存作品与生成URL分开：保存后是待导出状态，编辑过已导出的作品会标记为待重新导出，避免将旧图当作最新结果。刷新后可继续打开作品，上传失败重试可复用已缓存图片。清除站点数据会清除本地制作记录，服务端图片仍按存储策略保留。

旧版当前工作区的有效素材会在升级时一次性迁移到制作记录，原有导出历史继续保留。没有源文档的旧导出结果无法还原为可编辑作品。

## 验证

```bash
npm run check
npm run validate -- --root examples examples/basic/article.md examples/complex/article.md
# 浏览器验收；默认使用 /usr/bin/chromium，可通过 CHROMIUM_PATH 指定
npm run test:e2e
```

浏览器测试在生产构建上验证30份真实素材、ZIP导入、模板切换、长图底部像素、上传故障与仅上传重试、ZIP内容、JPEG、图片错误清理及结果恢复。需允许本地端口及Chromium进程运行。其他平台可安装Chromium并设置CHROMIUM_PATH。

## 整页海报模板

在「制作预览」中选择「蓝色健康海报」或「粉色专题海报」，左侧会切换为内容填充表单。背景、装饰、白色坑位由模板统一提供；表单支持标题、导语、正文、主视觉、坑位图片和品牌标识。

勾选「图片铺满坑位内部」可用已设计好的图文图片填满白框内部；不勾选时图片作为图标搭配标题与正文。支持添加、移除白色坑位，内容多时框体自动撑高。背景图片本身不要包含待替换的文字；人物、产品、图表素材可以分别上传。

点击「导出可编辑素材包」保留填充配置与上传图片，后续导入ZIP可继续编辑。原有三套Markdown模板和批量生产流程继续可用。

## 累计导出记录

「导出历史」独立保存每次成功导出的记录，包含时间、标题、文件名、模板、图片格式、倍率和URL。新建批次、再次导出同一素材或导入新项目都不会覆盖历史；同名、同内容图片仍分别记录。支持按标题/文件名搜索、查看全部历史或仅本次任务，并按筛选结果导出CSV和ZIP。

历史记录保存在当前浏览器的IndexedDB中；升级后会迁移仍保留在旧任务列表中的成功结果，无法追溯此前已经被覆盖的批次。清除浏览器站点数据会清除历史列表，服务端图片仍按部署存储策略保留。
